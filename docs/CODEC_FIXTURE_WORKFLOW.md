# Codec Fixture Workflow

`pixeldata/codecfixture` is the shared fixture and conformance harness for
optional pixel codec work. It builds deterministic synthetic DICOM objects in
memory and can serialize those objects as Part 10 files for application-level
tests.

## Fixture Location

- Reusable builders and conformance helpers live in `pixeldata/codecfixture`.
- Future on-disk fixtures belong under `pixeldata/codecfixture/testdata/codecs/`.
- A future fixture manifest should live at
  `pixeldata/codecfixture/testdata/codecs/manifest.json` and list each fixture's
  transfer syntax, size class, expected outcome, provenance, license or
  permission notes, and no-PHI statement.

## Provenance Rules

Synthetic fixtures are the default. They should be generated from simple pixel
arrays or deterministic codestream encoders and must not contain patient data.

Any de-identified fixture must include:

- source/provenance notes;
- license or permission notes;
- an explicit no-PHI statement;
- the de-identification method used before the file entered the repository.

Fixtures without that metadata should not be committed.

## Validation Workflow

Run these from `dicom-go/`:

```sh
make codec-conformance-check
make codec-fixture-bench
```

`codec-conformance-check` validates the baseline synthetic matrix. It covers
native uncompressed, RLE Lossless, JPEG Extended, JPEG Lossless, malformed
streams, unsupported metadata, metadata mismatches, missing optional adapters,
dependency-unavailable adapters, multi-frame native data, and
decompression-to-native behavior for the supported synthetic codecs. JPEG
Lossless coverage includes the independent exact RGB fixture returned by
`codecfixture.JPEGLosslessSV1RGB8Interleaved`.

`codec-fixture-bench` runs benchmark smoke cases for small, medium and large
synthetic frames with `-benchmem`. Benchmark latency and allocation numbers are
captured for comparison, but normal test pass/fail does not depend on specific
benchmark values.

Optional codec modules can reuse `pixeldata/codecfixture.Case` and
`ValidateCase` for their adapter-specific fixtures without moving optional
dependencies into the base module.

## JPEG Extended Process 4 qualification

The default `pixeldata/jpeg` tests include a deterministic 12-bit SOF1 stream
generated by libjpeg-turbo 3.1.0 and compare the pure-Go output with the
independent `djpeg` reference samples. They also cover invalid DQT/DHT tables,
invalid precision and dimensions, metadata mismatches, DICOM Item padding,
concurrent use of one codec instance, and a bounded fuzz target.

An installed libjpeg-turbo 3.x can regenerate and compare the stream, including
restart-marker handling:

```sh
DICOMGO_JPEG12_INTEROP=1 go test ./pixeldata/jpeg -run LibjpegTurbo -v
```

Additional vendor interoperability checks consume a separately obtained
GDCMData checkout without copying its files into this repository:

```sh
DICOMGO_GDCMDATA_ROOT=/path/to/GDCMData go test ./pixeldata/jpeg -run GDCMData -v
```

The GDCMData repository does not provide clear repository-level licensing for
these fixtures, so its files are not vendored. The opt-in gate treats the
SIEMENS and GDCM Process 4 streams as positive cases, and separately verifies
fail-closed handling of a PHILIPS stream with noncanonical lossy DC Huffman
symbols and a legacy DCMTK object whose Bits Allocated value is 12.

## JPEG Lossless multicomponent qualification

The default `pixeldata/jpeglossless` tests and shared codec fixture embed a
deterministic 4x3 unsigned RGB Process 14 SV1 stream generated with
libjpeg-turbo 3.1.0:

```sh
cjpeg -precision 8 -lossless 1,0 -rgb \
  -sample 1x1,1x1,1x1 input.ppm
```

The codestream SHA-256 is
`c9643dc57a6e631865084223af411c514d52edc30caaa3fe99eab5c9561d7e68`.
Expected interleaved samples come from `djpeg -strict -rgb -pnm`, so exact
comparison does not reuse the package under test. A second independent stream
uses three single-component scans with predictors 1, 2, and 7 to qualify
component-ID mapping, scan-local predictors, and scan-local point transforms.
Both sources are synthetic, contain no PHI, and are safe to redistribute with
the repository. The DICOM integration fixture declares PixelRepresentation 0,
PlanarConfiguration 0, RGB, and full-resolution 1x1 sampling.
