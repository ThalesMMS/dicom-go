# OpenJPEG Fallback Profile

Date: 2026-06-22

Issue: [#136](https://github.com/ThalesMMS/go-dev/issues/136)

## Decision

`jpeg2000_openjpeg` is an explicit native fallback profile for JPEG 2000 Part 1
codestreams that the controlled pure-Go profile cannot qualify as clinical
production coverage.

This profile does not replace `jpeg2000` and does not affect default builds.
Applications must opt in by building with `-tags jpeg2000_openjpeg` or by
calling `RegisterOpenJPEG` / `RegisterOpenJPEGDefault` from the optional nested
module.

`RegisterOpenJPEG` registers OpenJPEG for JPEG 2000 Part 1 still-image transfer
syntaxes and keeps JPEG 2000 Part 2 plus HTJ2K registered through the pure-Go
fallback. That split lets codec-full validation use OpenJPEG where it has been
qualified without regressing existing Twin-Viewer HTJ2K behavior.

## Backend

The current fallback invokes OpenJPEG's `opj_decompress` executable and converts
its binary PGM/PPM output back to DICOM native frame bytes. This keeps the base
module free of CGO and native library link requirements while still validating
against the OpenJPEG decoder implementation.

OpenJPEG tool discovery order:

1. `OpenJPEGExecutable(path)` option.
2. `DICOM_GO_OPENJPEG_DECOMPRESS` environment variable.
3. `opj_decompress` on `PATH`.

Missing executable or untagged builds return the typed
`ErrOpenJPEGUnavailable` error. The subprocess has a default 30 second per-frame
timeout, configurable with `OpenJPEGTimeout(duration)`. Captured process output
is bounded, the generated PNM file is size-checked before reading, and PNM
precision must match DICOM `BitsStored`.

## When To Use

Use `jpeg2000_openjpeg` when:

- an external/OpenJPEG-generated JPEG 2000 codestream does not round-trip through
  the pure-Go backend;
- a clinical codec-full build needs a native fallback for JPEG 2000 Part 1
  still images;
- JPEG 2000 Part 2 or HTJ2K files must keep using the existing pure-Go fallback
  inside the same tagged profile;
- packaging can provide the OpenJPEG runtime tools.

Keep using `jpeg2000` when:

- dependency-free builds are required;
- the controlled pure-Go fixture-backed profile is enough;
- OpenJPEG tools are not available on the target machine.

## Current Coverage

The OpenJPEG profile is tested with OpenJPEG-generated JPEG 2000 lossless and
lossy codestreams through the shared `pixeldata/codecfixture` harness. The same
fixtures are compared against the pure-Go backend to prove that the fallback
covers codestreams the pure-Go backend currently decodes incorrectly.

Twin-Viewer has a `LoadDICOMPaths` integration test under
`-tags jpeg2000_openjpeg` that loads an OpenJPEG-generated Part 10 file through
`internal/viewer/study`. The existing `jpeg2000` viewer test suite also runs
under combined `-tags 'jpeg2000 jpeg2000_openjpeg'` to prove HTJ2K remains
displayable through the pure-Go fallback when OpenJPEG is selected.

HTJ2K remains on the pure-Go controlled profile until an OpenJPEG/OpenJPH/Grok
or equivalent fallback path is explicitly qualified for HTJ2K. The local
OpenJPEG 2.5.4 `opj_decompress` tool does not currently decode the HTJ2K
fixture generated by the pure-Go encoder.

## License And Packaging

OpenJPEG is released under the BSD 2-clause license:

- [OpenJPEG project license](https://github.com/uclouvain/openjpeg/blob/master/LICENSE)
- [OpenJPEG project site](https://www.openjpeg.org/)

Packaging requirements:

- macOS/Homebrew: install `openjpeg`; ensure `opj_decompress` is on `PATH` or set
  `DICOM_GO_OPENJPEG_DECOMPRESS=/opt/homebrew/bin/opj_decompress` on Apple
  Silicon Homebrew installations.
- Windows: ship `opj_decompress.exe` plus the OpenJPEG runtime DLLs in the app
  bundle or installer, and set `DICOM_GO_OPENJPEG_DECOMPRESS` if the executable
  is not on `PATH`.
- Linux: install the distribution OpenJPEG package that provides
  `opj_decompress`, or ship the executable and required shared libraries with
  the application.

The OpenJPEG project documents the current executable names as `opj_compress`
and `opj_decompress` in its codec documentation:

- [OpenJPEG codec tool documentation](https://github.com/uclouvain/openjpeg/wiki/DocJ2KCodec)

Transitive dependency audit for the local macOS/Homebrew qualification:

| Component | Observed version/source | License reported by package manager | Packaging responsibility |
|---|---|---|---|
| OpenJPEG `opj_decompress`, `opj_compress`, `libopenjp2` | Homebrew `openjpeg` 2.5.4 | BSD-2-Clause | Required runtime executable and library for this profile. |
| `libpng` | Homebrew `libpng` 1.6.58 | libpng-2.0 | Direct Homebrew dependency of `openjpeg`; ship when bundling dynamic libraries. |
| `libtiff` | Homebrew `libtiff` 4.7.1 | libtiff | Direct Homebrew dependency of `openjpeg`; ship when bundling dynamic libraries. |
| `little-cms2` | Homebrew `little-cms2` 2.19 | MIT | Direct Homebrew dependency of `openjpeg`; ship when bundling dynamic libraries. |
| `zlib`, `libSystem` | macOS system libraries observed by `otool -L` | OS-provided | Do not vendor separately on macOS; verify equivalent platform libraries elsewhere. |
| `jpeg-turbo`, `xz`, `zstd`, `lz4` | Declared transitive Homebrew dependencies through `libtiff` / `little-cms2` | Mixed permissive and copyleft formula metadata | Reaudit before app bundling; do not vendor GPL-only artifacts without distribution approval. |

Windows and Linux builds must repeat this audit against the exact installer or
distribution packages being shipped. The `dicom-go` repository does not vendor
OpenJPEG binaries or their transitive runtime libraries.
